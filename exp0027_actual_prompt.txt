# EXP-0027 — Hybrid Evidence-Grounded NLI Verifier

You are continuing the forensic evolution of `EduConnect-LMS-Experimental`.

## STATUS OF PRIOR EXPERIMENTS

Do not alter `EduConnect-LMS-Production`.

The authoritative experimental history is:

* EXP-0023 exposed major false-premise, prompt-injection, and feature-flag weaknesses.
* EXP-0024 introduced an evidence-grounded verifier and fixed the unauthenticated safety-flag boundary, but failed the FAR/refutation gates.
* EXP-0025 improved the reported holdout results substantially:

  * FAR = 7.67%
  * Refutation Recall = 85.33%
  * Legitimate Negation FRR = 0%
  * Unknown Recall = 100%
* EXP-0026 independently reproduced EXP-0025 but demonstrated severe rule dependency:

  * removing the 138 semantic-opposite dictionary reduced refutation recall from 92% to 9%;
  * concept-generalization recall on uncovered concepts fell to 10%;
  * cross-rule adversarial refutation recall = 0%;
  * fresh blind dataset: Accuracy = 57.90%, FAR = 23.33%, Refutation Recall = 30%;
  * historical 2,000-case regression: Accuracy = 60.75%, FAR = 27.17%, Refutation Recall = 37%.

Therefore:

**EXP-0025 is NOT a generalizable NLI verifier.**

It is frozen as a curriculum-scoped heuristic baseline.

EXP-0027 must test whether a genuinely semantic evidence-comparison layer can remove this dependency.

# 1. RESEARCH QUESTION

Investigate:

"Can a hybrid verifier combining a fast deterministic curriculum path with a generic semantic entailment/contradiction model generalize to previously uncovered propositions while preserving safety, legitimate-negation handling, and the closed-domain evidence boundary?"

Do not optimize directly against the old benchmark.

Do not reproduce the 138-pair dictionary at a larger scale.

Do not replace one benchmark-specific rule catalogue with another.

# 2. EXP-0027 EXPERIMENTAL ARCHITECTURE

Implement a two-tier verifier.

## Tier 1 — Deterministic Fast Path

Retain EXP-0025's existing deterministic mechanisms only where they are demonstrably useful:

* known high-confidence curriculum misconception mappings;
* basic syntactic normalization;
* safe structural parsing;
* explicit legitimate-negation handling;
* clearly validated safety rules.

Do NOT add new benchmark-specific semantic mappings.

Do NOT expand the semantic-opposite dictionary.

Treat the existing 138-pair dictionary as a frozen Tier-1 baseline, not as the future reasoning engine.

Record whether a case was resolved by Tier 1.

## Tier 2 — Generic Evidence-Grounded Semantic Verification

Cases not confidently resolved by Tier 1 must be evaluated using a semantic entailment/contradiction model over retrieved evidence.

The design should conceptually evaluate:

`QUERY PROPOSITION`
against
`RETRIEVED EVIDENCE`

and produce:

* ENTAILMENT
* CONTRADICTION
* UNKNOWN / INSUFFICIENT EVIDENCE

Then map those states to:

* SUPPORTED
* REFUTED
* NOT_ESTABLISHED

The semantic model must NOT be given the ground-truth label.

It must consume real retrieved curriculum evidence.

Premise verification must not search external knowledge.

Only retrieved curriculum evidence may establish:

or
REFUTED.

# 6. PROPOSITION EXTRACTION

Use a generic proposition extraction mechanism.

Separate:

* assertion content
* question framing
* negation
* contrastive clauses
* conditionals
* modifiers
* quantities
* temporal constraints
* causal relationships

The key requirement is that:

"Why does X not allow Y?"

must not be interpreted as:

"X allows Y."

Likewise:

"Why does ROLLBACK permanently commit changes?"

contains a proposition about ROLLBACK behavior that must be compared with evidence rather than treated as a keyword collision.

Do not rely solely on regex for proposition semantics.

---

# 7. EVIDENCE SENTENCE SELECTION

From retrieved chunks:

1. split into evidence units/sentences;
2. calculate semantic relevance to the proposition;
3. evaluate only the highest-quality evidence units;
4. preserve evidence provenance.

Do not pass large duplicated contexts blindly to the model.

For each proposition record the selected evidence.

---

# 8. CONTRADICTION LOGIC

Contradiction must require semantic incompatibility.

Examples of incompatible relationships include:

* opposite state
* opposite capability
* incompatible operation
* contradictory numeric value
* contradictory scope
* contradictory temporal statement
* contradictory causal relationship

Simple lexical overlap MUST NOT constitute contradiction.

The system must be able to recognize contradiction even where vocabulary differs substantially.

This is the central research objective.

---

# 9. UNKNOWN / ABSTENTION LOGIC

The semantic model may produce uncertainty.

Do not force binary decisions.

Use a conservative decision layer:

High-confidence entailment -> SUPPORTED

High-confidence contradiction -> REFUTED

Otherwise -> NOT_ESTABLISHED

Calibrate thresholds on development data only.

Do not tune thresholds on any blind holdout.
