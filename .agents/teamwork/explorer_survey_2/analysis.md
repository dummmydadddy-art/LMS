## 2. Linear Cosine Scan in `getPrewarmedCorpus()` vs. ANN Vector Index

### 2.1 Current Implementation in `backend/rag_service.php`
- **Location**: `backend/rag_service.php`, lines 371–466 (`getPrewarmedCorpus()`), lines 1437–1475 (`searchCore()`), and lines 1243–1278 (`searchMissingModule()`).
- **Mechanism**:
  1. On first request or version bump, `getPrewarmedCorpus()` executes `SELECT ... FROM material_chunks`.
  2. Iterates all 1,323 rows in PHP. For each row:
     - Calls `self::unpackVector($r['embedding'])` (3,072-byte string unpack).
     - Validates 7 initialization invariants (throws `RuntimeException` if dimension $\ne 768$, norm $\le 0$, etc.).
     - Normalizes each vector to a unit vector: `$unit = array_map(fn($v) => $v / $norm, $vec);`.
     - Tokenizes text and counts word frequencies for BM25: `$docTokens = array_count_values(self::tokenize($text));`.
     - Stores the full structure in static memory `self::$prewarmedCorpus`.
  3. At query time in `searchCore()`:
     ```php
     // Lines 1458-1472
     foreach ($candidates as $idx => $row) {
         $uVec = $row['unit_vector'] ?? [];
         if (!is_array($uVec) || count($uVec) !== $dim) continue;
         $dot = 0.0;
         for ($i = 0; $i < $dim; $i++) {
             $dot += (float)$qUnit[$i] * (float)$uVec[$i];
         }
         $row['similarity'] = round($dot, 4);
         $candidatesWithVectors[$idx] = $row;
         $denseScored[$idx] = $dot;
     }
     arsort($denseScored);
     ```
  4. BM25 is scored across all candidate documents via `scoreBM25Precomputed()` (lines 471–515).
  5. Reciprocal Rank Fusion (RRF) combines the dense ranking and BM25 ranking (lines 1525–1526).

### 2.2 Shortcomings of the Current Approach
1. **CPU/Interpreter Overhead**: Calculating $1,323 \times 768 = 1,016,064$ floating-point multiplications in PHP userland loops on every search call takes considerable CPU cycles.
2. **Scalability Ceiling**: As the corpus grows to 5,000 or 10,000 chunks, memory usage and linear scan latency grow linearly $O(N)$, violating sub-500ms total pipeline budgets.
3. **Redundant Memory Footprint**: Unpacked float arrays in PHP consume significantly more memory than native C binary vectors (PHP zvals overhead is ~32 bytes per float element $\approx 24\text{ KB}$ per vector vs 3 KB raw).

### 2.3 Proposed ANN Architecture with `sqlite-vec`
With `sqlite-vec` virtual table `vec_material_chunks`:
- Vector similarity search is delegated to SQLite's native C extension using SIMD-accelerated distance kernels.
- Query syntax:
  ```sql
  SELECT chunk_id, distance
  FROM vec_material_chunks
  WHERE embedding MATCH :query_vector_blob
    AND k = :k_dense;
  ```
- Similarity calculation: `similarity = round(1.0 - distance, 4)`.
- Query time drops from ~80–120ms (PHP array unpack + loop) to **~10–12ms**.
- Dense candidates (top 40–50) are retrieved directly from SQLite, and BM25 can be evaluated on that high-relevance candidate pool or fused with candidate BM25 matches.

### 3.2 PHP Extension Loading Mechanics
Our direct investigation uncovered a vital distinction between PHP database drivers:

1. **`PDO_SQLITE` (Does NOT support extension loading)**:
   - When attempting `SELECT load_extension('vec0.dll')` via `PDO`:
     `SQLSTATE[HY000]: General error: 1 not authorized`
   - Reason: PHP's PDO SQLite driver does not call `sqlite3_enable_load_extension()`. This is a hard-coded security limitation in PHP's PDO core.
2. **`SQLite3` class (FULLY supports extension loading)**:
   - The `sqlite3` extension is already enabled in `bin/php.ini` (`extension=sqlite3`).
   - By default, PHP disables `SQLite3::loadExtension()` if `sqlite3.extension_dir` is not configured (`SQLite Extensions are disabled`).
   - When `sqlite3.extension_dir` is defined in `bin/php.ini`:
     ```ini
     sqlite3.extension_dir = "ext"
     ```
     Calling `$db = new SQLite3($dbPath); $db->loadExtension('vec0.dll');` succeeds immediately!
   - Verification test:
     ```php
     $db = new SQLite3(':memory:');
     $db->loadExtension('vec0.dll');
     echo $db->querySingle("SELECT vec_version()"); // Returns: 'v0.1.9'
     ```
3. **FrankenPHP Runtime Compatibility**:
   - `bin/frankenphp.exe` loads `bin/php.ini` directly (verified via `php_ini_loaded_file()` $\to$ `D:\Collage project\EduConnect-LMS-Experimental\bin\php.ini`).
   - Setting `sqlite3.extension_dir = "ext"` in `bin/php.ini` applies to both CLI and FrankenPHP web worker processes.

### 4.3 Proposed Parent-Child Hierarchical Schema (R4)
To implement R4:
1. **New Table**: `parent_chunks` in `backend/storage/vectors.sqlite`:
   ```sql
   CREATE TABLE parent_chunks (
       id TEXT PRIMARY KEY,
       material_id TEXT,
       title TEXT,
       content TEXT,
       metadata TEXT,
       token_count INTEGER,
       created_at DATETIME DEFAULT CURRENT_TIMESTAMP
   );
   CREATE INDEX idx_parent_mat ON parent_chunks(material_id);
   ```
2. **Alter `material_chunks`**:
   ```sql
   ALTER TABLE material_chunks ADD COLUMN parent_chunk_id TEXT;
   CREATE INDEX idx_chunks_parent ON material_chunks(parent_chunk_id);
   ```
3. **Hierarchical Ingestion Strategy**:
   - When parsing textbook chapters/sections:
     - **Parent Chunk**: Aggregate consecutive paragraphs into a bounded context window of **~800–1000 tokens** (~3,200–4,000 characters). Store in `parent_chunks`.
     - **Child Chunks**: Within that parent window, generate **~200 token** (~700–900 characters) child chunks with 50-token overlap.
     - Each child chunk gets embedded via Ollama `nomic-embed-text` and stored in `material_chunks` (with `parent_chunk_id` set) and `vec_material_chunks`.
     - Ratio: ~3 to 4 child chunks per parent chunk.
4. **VRAM and Generation Safety**:
   - Parent chunks are stored purely as text in SQLite (zero VRAM overhead).
   - Context window for `llama3.2:latest`: Passing 2–3 parent chunks (~2,000 context tokens) uses ~2.1 GB VRAM, leaving ~1.9 GB headroom on the RTX 3050 (4 GB limit).

### 5.2 Retrieval Code Integration Points in `rag_service.php`
1. **Helper Method**: `RagService::getVectorDb(): SQLite3`
   ```php
   public static function getVectorDb(): SQLite3 {
       if (self::$vectorDb === null) {
           $dbPath = __DIR__ . '/storage/vectors.sqlite';
           self::$vectorDb = new SQLite3($dbPath);
           self::$vectorDb->loadExtension('vec0.dll');
       }
       return self::$vectorDb;
   }
   ```
2. **Querying ANN in `searchCore()`**:
   ```php
   $qBlob = self::packVector($queryEmbedding);
   $vDb = self::getVectorDb();
   $stmt = $vDb->prepare("
       SELECT chunk_id, distance
       FROM vec_material_chunks
       WHERE embedding MATCH ? AND k = :k_dense
   ");
   $stmt->bindValue(1, $qBlob, SQLITE3_BLOB);
   $stmt->bindValue(':k_dense', 40, SQLITE3_INTEGER);
   $res = $stmt->execute();
   // Populate dense candidates with similarity = round(1.0 - distance, 4)
   ```
3. **Parent Context Injection**:
   ```php
   // In searchCore() or before compressContext() in ask():
   $parentIds = array_filter(array_column($topResults, 'parent_chunk_id'));
   if (!empty($parentIds)) {
       $uniqueParentIds = array_unique($parentIds);
       $parentChunks = self::fetchParentChunks($uniqueParentIds);
       foreach ($topResults as &$child) {
           if (!empty($child['parent_chunk_id']) && isset($parentChunks[$child['parent_chunk_id']])) {
               $child['child_content'] = $child['content'];
               $child['content'] = $parentChunks[$child['parent_chunk_id']]['content'];
           }
       }
   }
   ```
4. **Fallback Safety**: If `parent_chunk_id` is null (such as the 23 baseline curriculum notes), the pipeline uses `$child['content']` directly without error.
